# Телеграм-бот кампании — проект (TG-00)

Статус: **на одобрении автора** (составлен 2026-11-20). Код — после одобрения, задачами TG-01…TG-04 в `TODO.md`.
Вопросы, на которые нужен ответ автора, собраны в конце, в разделе «Решить автору».

## Зачем и в каких границах

Сервер живёт только в домашней сети (PH-10), без HTTPS. Бот даёт малый набор функций вне её: бросок, проверку навыка,
выстрел оружием в руках — и сообщает «твой ход» вместо отменённого Web Push (PH-13). Всё остальное — в приложении.

Главный критерий — **меньше сообщений и меньше ввода**: ответ на команду — одно сообщение, меню кнопок правится на месте,
события кампании — только нужные, подряд идущие склеиваются (слово автора от 2026-11-17: «бот не должен засорять эфир»).

Бот — ядро `[CORE]`, пакет `app.charka.telegram`. Кубики, навыки, оружие и формулировки берёт только у `GameSystem` и его
частей: ни строчки CP2020 или Космозэков в боте.

## 1. Связь с Telegram

**Длинный опрос** (`getUpdates`, `timeout=50`): сервер сам ходит к `api.telegram.org`, входящие подключения, белый IP
и HTTPS не нужны. Один поток-демон (`TelegramPoller`, `SmartLifecycle`: стартует после контекста, останавливается
при выключении), не `@Scheduled` — опрос висит до 50 с, ему нужен свой поток.

**Клиент — свой, тонкий**, на `RestClient` Spring (уже в зависимостях): нужно 5 методов — `getUpdates`, `sendMessage`,
`editMessageText`, `answerCallbackQuery`, `getMe`. Библиотека `org.telegram:telegrambots` даёт сотни классов, свой
поток опроса и свою модель обновлений, а нам нужен JSON пяти методов: берём свой, ~200 строк с DTO-записями.
Сравнение:

| | Свой на `RestClient` | `telegrambots` |
|---|---|---|
| Зависимость | нет | +1 библиотека, свои транзитивные (Jackson, httpclient) |
| Поток опроса | наш, видно в коде | их, настраивается их API |
| Тесты | `MockRestServiceServer` или подмена интерфейса `TelegramApi` | их моки |
| Новое в Bot API | дописать поле в запись | обновить версию |

**Токен** — переменная `CHARKA_TELEGRAM_TOKEN` (`charka.telegram.token` в `application.yml`). Нет токена — бот
выключен целиком: бины опроса и отправки не создаются (`@ConditionalOnProperty`), в «Настройках» кампании вместо
кнопки «Привязать Telegram» — строка «Бот не настроен». В тестах токена нет; тесты бота подменяют `TelegramApi`.
Бота у @BotFather создаёт автор: `/newbot`, затем `/setprivacy` → Enable (раздел 11), `/setcommands` — список из раздела 7.

**Сеть.** Если у окружения сервера ограничен выход наружу — нужен `api.telegram.org:443`. Прокси не нужен.

## 2. Старые сообщения

Решено автором 2026-11-17: **отбрасывать молча.** При старте опроса: `getUpdates` с `offset=-1` (вернёт последнее
обновление), запомнить его `update_id + 1` и начать с него. Накопленное за время выключения не выполняется, ответов на
него нет. Из этого следует: `offset` в БД хранить **не нужно** — после каждого старта он вычисляется заново
(изменение плана: в TG-00 предполагалось хранить; запись в журнал решений).

Нажатие кнопки старого меню после перезапуска приходит как обычный `callback_query` — оно выполняется, если его данные
ещё верны (раздел 7, «Кнопки»), иначе ответ всплывашкой «Меню устарело — /attack заново».

## 3. Привязка беседы к кампании

Мастер в «Настройках» кампании (R-13) нажимает **«✈ Привязать Telegram»** → ссылка и QR
`https://t.me/<бот>?startgroup=g<код>`. По ней Telegram предлагает выбрать группу; бот приходит в неё с командой
`/start g<код>` и привязывает беседу. Код одноразовый, живёт 1 час, 16 случайных символов (`SecureRandom`, как
приглашение A-02).

- Одна беседа — одна кампания; одна кампания — одна беседа. Новая привязка кампании отвязывает старую беседу
  (бот пишет в неё «Беседа отвязана от кампании»).
- Отвязать — кнопкой там же; бот из группы не выходит, просто перестаёт отвечать (команды — «Беседа не привязана»).
- Бота удалили из группы (`my_chat_member` со статусом `left`/`kicked`) — привязка снимается сама.
- Группа стала супергруппой — Telegram присылает `migrate_to_chat_id`: переписать id беседы.

Нажатий мастера: «⚙» → «Привязать Telegram» → (в Telegram) выбрать группу → «Добавить» = **4**.

## 4. Привязка человека

На листе персонажа и в меню аккаунта — **«✈ Telegram»** → ссылка `https://t.me/<бот>?start=u<код>` (одноразовый, 1 час).
В личке боту приходит `/start u<код>`: telegram-пользователь (`from.id`) связывается с `AppUser`. Ответ: «Готово,
<логин>. В беседе кампании бот узнает вас сам». Один telegram-пользователь — один `AppUser` (новая привязка заменяет
старую).

В беседе бот узнаёт игрока по `from.id`:
- не привязан — ответ одним сообщением с кнопкой-ссылкой «Привязать» (ведёт на лист в приложении, где кнопка
  «✈ Telegram»; сам код в беседу не шлём — его увидят все);
- привязан, но в кампании нет его персонажа — «У вас нет персонажа в «<кампания>»»;
- персонаж один — действует за него;
- персонажей несколько — первое действие спрашивает кнопками «За кого?», выбор запоминается
  (`telegram_user.last_character_id` по кампании) и меняется командой `/me`.

Нажатий игрока на привязку: «✈ Telegram» → «Запустить» в Telegram = **2**, один раз.

## 5. Права — те же, что в приложении

Все действия идут через существующие сервисы (`DiceService`, `CheckService`, `SkillService`, `AttackService`,
`RollRequestService`). Права проверяются теми же классами, что и для HTTP:

- **Кто действует.** `AccessService.current()` читает пользователя из `SecurityContextHolder`. Обработчик команды
  ставит в контекст `Authentication` привязанного `AppUser` (как после входа) и снимает его в `finally` — сервисы,
  `AccessService.canControl` и `TurnGuard` работают без изменений. Это делает одно место — `TelegramActions` (раздел 6).
- **Ход.** `TurnGuard.waitsForTurn(character)` уже есть: в бою вне своего хода бот отказывает «Сейчас ходит X» в
  атаке. Бросок выражения и проверка навыка вне хода — как в приложении: закрыты `TurnGuard`, кроме того, что в
  `CHARACTER_ALLOWED` (спасброски). Список не дублируем — бот спрашивает у `TurnGuard` по тому же пути маршрута,
  которым это действие сделано в приложении (метод `TurnGuard.check(character, route)` вынести из `preHandle`).
- **Мастер.** Из беседы за NPC **не кидает** (автор, 2026-11-17). Что мастеру можно через бота, пришлёт автор —
  до тех пор у мастера в беседе работает только `/r` (бросок от имени кампании, как кубики на странице кампании).

## 6. Отмена, блокировка, журнал

Сейчас `CampaignLock` (VER-01), `UndoInterceptor` (A-01), `TurnGuard` (TURN-01) и `ActionLog` (LOG-01) —
`HandlerInterceptor`: они видят только HTTP. Бот HTTP не проходит.

**Решение — одна обёртка «действие кампании»** `app.charka.undo.CampaignAction` (сервис, ядро):

```java
<T> T run(long campaignId, Long characterId, String label, String source, Supplier<T> action)
//  1. CampaignLock.acquire(campaignId)            — тот же замок в памяти, 409/«занят» после WAIT_SECONDS
//  2. snapshot = UndoService.snapshot(campaignId) — снимок «до»
//  3. result = action.get()                       — в транзакции сервиса
//  4. UndoService.record(snapshot, label, characterId) — запись отмены: «↶ Отменить» в приложении работает
//  5. ActionLog: «campaign=7 user=kolya via=telegram action=/attack … ok»
//  6. finally: CampaignLock.release(campaignId)
```

Перехватчики переписываются на неё же (их `preHandle`/`afterCompletion` зовут те же шаги), чтобы порядок жил в одном
месте, а не в двух копиях. Это небольшая правка ARC-03 попутно: публичные `acquire/release` у `CampaignLock`,
`ActionLog.line(...)` — статический форматтер строки.

Отмена в беседе не предлагается (лишнее сообщение): действие из бота отменяется в приложении, плашкой в ленте
«↶ Отменить» у автора или мастера — как сейчас.

## 7. Команды и кнопки

Ниже «нажатие» — нажатие кнопки, «ввод» — набор текста. Сравнение — с приложением на телефоне сегодня.

### `/r` — бросок

- `/r 2d6+1` → одно сообщение: **«Колясик: 2d6+1 = 9** (4, 4, +1)». Пишется в `RollLog` кампании от персонажа,
  видно в ленте приложения с пометкой ✈.
- `/r` без аргумента → сообщение с кнопками быстрых кубиков системы (`GameSystem` уже отдаёт: CP2020 — d10, d6;
  Космозэки — к100, к12, …). Нажатие правит **это же** сообщение на итог броска. 2 действия: `/r` + кнопка.
- `/r к100`, `/r d100` — русские «к» принимаются (как в поле чата).

### `/check` — проверка навыка

- `/check` → кнопки «Частых навыков ☆» персонажа (`SkillService.frequentChecks`), до 8; последняя — «🔍 Другой…»
  (бот просит ответить сообщением с началом названия). Нажатие → проверка со сложностью по умолчанию системы.
- `/check внимат` → поиск по началу и по подстроке названия (`SkillService.checkOptions`); одно совпадение —
  сразу бросок, несколько — кнопки.
- `/check стрел 15` — последнее число — сложность. У Космозэков проверка — 1к12 против сложности числом
  (`getTableCheckResolver`, KF-09) — бот берёт резолвер у системы, как чат приложения.
- Итог — одно сообщение: «**Колясик · Внимательность: 17 против 15 — успех**», ниже одной строкой расчёт
  (уровень + стат + кубик). Криты и провалы помечены, как PH-22.

Нажатий: частый навык — 2 (`/check` + кнопка); по имени — 1 ввод.

### `/attack` — атака оружием

Меню одним сообщением, которое правится на месте по шагам:

1. **Оружие.** В руках (`mainWeaponId`) — первым и уже выбранным: шаг пропускается, если у персонажа одно оружие
   или оружие в руках есть. Иначе — кнопки оружия носимого инвентаря + «Драка» (способность системы).
2. **Цель.** В бою — участники, видимые атакующему (`BattleFieldService` с туманом M-16, как карта игрока),
   по возрастанию расстояния; вне боя — «Без цели» (как «неназванная цель» в приложении).
3. **Дистанция.** В бою, если обе фишки на карте — считается по карте (как линейка), шаг пропускается. Иначе —
   кнопки диапазонов системы (`AttackRules.form` отдаёт диапазоны: «вплотную · близко · средне · далеко ·
   предельно» со значениями в метрах).
4. **Режим** — только если оружие умеет больше одного (`AttackForm.modes`): «одиночный · очередь · …».
   Иначе шаг пропускается.
5. Подтверждение не нужно: последнее нажатие стреляет. Итог правит меню: **«Колясик → Бандит: попадание, 7 урона
   в торс (SP 10 → 9)»**, ниже строка расчёта.

Остальное — значения по умолчанию, как в диалоге атаки: зона попадания — случайная, модификаторы — 0, число
патронов — `defaultRounds`. Нужно больше (зона, укрытие, модификаторы FNFF, заряды по площади, `PendingBlast`) — кнопка
«Открыть в приложении» (ссылка на лист с открытым диалогом атаки).

Нажатий на типичный выстрел в бою (оружие в руках, фишки на карте, один режим): `/attack` + цель = **2**.
В приложении на телефоне сегодня: «Атаковать» + цель + «Атаковать» = 3 (плюс открыть лист).

### Прочее

- `/me` — за кого играю (несколько персонажей) и его состояние одной строкой (`sheet().getHealthStatus`).
- `/help` — список команд одним сообщением.
- Команды, которые бот не знает, и обычная переписка — без ответа (раздел 11).

### Кнопки (callback)

`callback_data` ≤ 64 байт: `a:<menuId>:<шаг>:<значение>`. Состояние меню — в памяти (`Map<menuId, AttackDraft>`,
живёт 10 минут) — после перезапуска сервера старое меню отвечает «Меню устарело». Нажимать кнопку может только тот,
кто вызвал меню; чужое нажатие — всплывашка «Это меню Колясика» (`answerCallbackQuery`, в беседу не пишется).

## 8. Что идёт из кампании в беседу

| Событие | По умолчанию | Текст |
|---|---|---|
| Твой ход (замена PH-13) | **вкл** | «⚔ Ход: @kolya (Колясик)» — упоминание будит телефон |
| Запрос броска мастера (A-07) | **вкл** | «🎲 Мастер просит: Колясик, Олежа — Внимательность 15» + кнопка «Бросить» у каждого |
| Крит или провал (PH-22) | выкл | «💥 Колясик: критический успех» |
| Начало и конец боя | **вкл** | «⚔ Бой начался · раунд 1» / «Бой окончен» |

Выключатели — в «Настройках» кампании рядом с привязкой (поле `campaign_telegram.events`, набор кодов).

Не идут никогда: скрытые броски мастера (A-09); всё, что в тумане войны (M-16): ход NPC, которого игроки не видят,
пишется как «⚔ Ходит кто-то из врагов» или не пишется вовсе (ход скрытого NPC — склеить с ходом следующего видимого);
чат — ни в одну сторону.

**Отправка.** События публикуются из сервисов как Spring-события и уходят **после коммита**
(`@TransactionalEventListener(phase = AFTER_COMMIT)`): откатившееся действие не пишет в беседу. Очередь отправки —
одна на беседу, не чаще 1 сообщения в 3 с (лимит Telegram — ~20 в минуту в группу), события одной беседы за эти 3 с
**склеиваются в одно сообщение**: «Бой начался · раунд 1. Ход: @kolya» вместо двух. Ошибка Telegram (429) — повтор
через `retry_after`, остальные ошибки — в журнал, не повторять.

## 9. Хранение

Новые таблицы (миграция `V<n>__telegram.sql`), не игровое состояние: в `SnapshotTablesTest.NOT_SNAPSHOTTED`
с причиной «привязки бота, не игра», без `@Version`, не экспортируются.

```
telegram_user      (id, app_user_id UNIQUE → app_user, telegram_user_id BIGINT UNIQUE, username, linked_at)
telegram_chat      (id, campaign_id UNIQUE → campaign, chat_id BIGINT UNIQUE, title, events VARCHAR, linked_at)
telegram_character (telegram_user_id → telegram_user, campaign_id → campaign, character_id → character,
                    PK (telegram_user_id, campaign_id))               — «за кого» при нескольких персонажах
telegram_link_code (code PK, kind 'GROUP'|'USER', campaign_id?, app_user_id?, expires_at)
```

`offset` не хранится (раздел 2). Удаление кампании или пользователя удаляет привязки (`ON DELETE CASCADE`).

Броски, проверки и атаки из бота пишутся в `RollLog`/`JournalEntry` как обычные. Пометка источника — новая колонка
`source VARCHAR(16)` у `roll_log` и `journal_entry` (`NULL` — приложение, `TELEGRAM` — бот); лента показывает ✈.

## 10. Системы

Бот не знает правил: кубики — `GameSystem` (быстрые кубики, `DiceExpression`), проверки — `CheckService` и
табличный резолвер системы, навыки — `SkillService`, атака — `AttackService` с `AttackRequest`, собранным из тех же
значений по умолчанию, что диалог атаки. Чтобы не было двух копий умолчаний, сборку `AttackRequest` по умолчанию
вынести из контроллера и JS в `AttackRules.defaults(form)` (часть системы; у системы без атак — пусто) — её зовут и
контроллер, и бот.

Проверка TG-03: на обеих системах выстрел ботом и выстрел из приложения с теми же кубиками (`DiceRoller` — мок)
дают одинаковый `AttackResult` (тест на каждую систему).

## 11. Режим приватности

Бот в группе с **включённым** privacy mode видит только команды (`/…`, `/…@бот`), ответы на свои сообщения и нажатия
своих кнопок. Переписку группы он не получает и не читает. Это же требование к «🔍 Другой…» в `/check`: бот просит
**ответить** на его сообщение — ответ ему виден.
